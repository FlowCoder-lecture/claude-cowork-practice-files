# 실행 환경 점검표

| 항목 | 필요한 이유 | 최소 설정 | 확인 방법 | 상태 |
|---|---|---|---|---|
| Memory | 실행마다 브리핑 형식이 달라지지 않게 한다 | 반복 기준 세 문장 | briefing-rules.md와 같은 내용인지 대조 | 준비됨 |
| Skills | 같은 절차를 매일 반복한다 | 다섯 줄짜리 절차 문서 | 절차 문서만 보고 결과를 다시 만들 수 있는지 확인 | 확인 필요 |
| Connectors | 일정·메일·메시지·할 일을 읽는다 | 서비스별 읽기 도구만 허용 | connector-permissions.md와 실제 도구 목록 대조 | 확인 필요 |
| 예약 | 매일 오전 8시 전에 결과가 있어야 한다 | 매일 08:00 Asia/Seoul | 예약 목록에서 다음 실행 시각 확인 | 확인 필요 |
| 사람 검토 | 잘못된 결과가 다음 행동으로 넘어가지 않게 한다 | 검토자 1명, 항목 수와 날짜 확인 | 08:30까지 결과를 열어 확인 | 준비됨 |

상태는 준비됨, 사용 안 함, 확인 필요 세 가지만 사용합니다.

## 사용하지 않는 항목

| 항목 | 상태 | 이유 |
|---|---|---|
| 외부 메시지 발송 | 사용 안 함 | 완료 기준에 없는 행동이다 |
| 파일 저장소 연결 | 사용 안 함 | 이번 브리핑은 네 서비스만 읽는다 |
| 결제 정보 접근 | 사용 안 함 | 완료 기준에 없는 데이터다 |

## 샘플 데이터 리허설 순서

1. 샘플 일정 두 건과 샘플 할 일 한 건을 준비한다.
2. 서비스마다 한 줄씩 읽어 네 줄을 만든다.
3. 네 줄을 다섯 줄 브리핑으로 바꾼다.
4. 항목 수, 제목의 날짜, 개인 정보 잔존 여부를 사람이 확인한다.
5. 통과하면 실제 데이터로 한 번 더 실행하고, 외부 전송은 켜지 않는다.

## 실패를 확인할 위치

- 결과 파일이 생겼는지 먼저 본다.
- 실행 기록에서 서비스별 호출 결과를 본다.
- 08:30까지 결과가 없으면 사람이 수동으로 실행한다.
