# SECTION 01 프롬프트 모음

책에 실린 [프롬프트 입력]을 순서대로 모았습니다. 회색 상자 안의 글만 복사해 Claude 입력창에 붙여 넣습니다.
`[여기에 … 붙여 넣기]` 자리는 안내한 연습용 파일의 내용으로 바꿔 넣습니다.

## 웜업. 오늘의 요청 브리핑 카드

- 붙여 넣을 파일: `section-01/warmup-partner-emails.txt`

```text
아래는 이번 주에 받은 제휴 요청 메일 세 통이야. 오늘은 2026년 7월 24일 금요일이라고 가정해.

[여기에 메일 세 통 붙여 넣기]

이 내용으로 「오늘의 요청 브리핑」 카드를 한 장 만들어 줘.
1. 오늘 처리할 것 / 답을 기다리는 것 / 확인이 필요한 것, 세 칸으로 나눠.
2. 메일에 없는 값은 추측하지 말고 [확인 필요]로 표시해.
3. 회신 기한이 임박한 순서로 정렬해.
4. 화면에 붙여 둘 수 있게 한 장짜리 카드로 만들어 줘.
5. 카드는 HTML로 시각화하고, 기한이 임박한 항목은 눈에 띄게 강조해 줘.
```

## 따라 하기 4단계. 첫 자동화 후보 고르기

- 붙여 넣을 파일: `section-01/repeat-work-list.txt`
- 결과 예시: `section-01/work-card-01.md`

```text
내가 지난 2주 동안 반복한 업무 목록이야.

[여기에 업무 목록 붙여 넣기]

다음 기준으로 첫 자동화 후보를 하나 골라 줘.
1. 입력과 결과가 반복된다.
2. 결과를 사람이 확인할 수 있다.
3. 실패해도 원본을 잃지 않고 다시 할 수 있다.
4. 샘플 한 건으로 30분 안에 시험할 수 있다.

선택한 이유를 세 문장 이내로 써 줘.
아래 항목도 채워 줘.
- 업무 이름
- 시작 신호
- 입력
- 결과
- 사람이 확인할 항목 (한두 개만)
- 확인 뒤 사용할 곳
항목을 채운 다음, 같은 내용을 아래 두 줄 형식으로도 한 번 더 써 줘.
「[시작 신호]가 생기면 [입력]을 읽고 [결과]를 만든다.
 사람이 [사람이 확인할 항목]을 확인한 뒤 [확인 뒤 사용할 곳]에 쓴다.」
외부 전송, 삭제, 결제는 후보에서 제외해 줘.
결과는 work-card-01.md에 저장할 내용으로 보여 줘.
```

Claude가 1번이 아닌 다른 업무를 골랐다면 같은 대화에 아래 프롬프트를 입력합니다.

```text
이번 실습은 1번 업무로 진행할게.
1번 업무로 같은 형식의 반복 업무 카드를 다시 만들어 줘.
```

## 사례. 제휴 요청 검토 자동화하기

- 결과 예시: `section-01/case-partnership-work-card.md`

```text
나는 소규모 교육 회사를 운영해.
매주 금요일에 메일·소개 메시지·행사 신청서로 들어온 제휴 요청을 읽고 다음 주 답변 순서를 정해.
첫 자동화 범위는 '익명화한 제휴 요청 다섯 건을 검토 순서대로 배열하기'로 제한할 거야.
시작 신호는 금요일 오후 3시, 결과 파일은 partnership-review.md야.
분류 기준은 세 개만 써.
- 일정이 2주 안이면 '먼저 확인'
- 제안 내용과 희망 결과가 모두 있으면 '자료 충분'
- 금액과 계약 조건은 판단하지 말고 '사람 검토'
답장 발송, 금액 결정, 일정 확정은 내가 직접 해.
업무 이름, 시작 신호, 입력, 결과, 사람이 확인할 항목, 자동화하지 않는 일을 표로 정리해 줘.
```

## 잘못된 결과를 바로잡는 대화 ①. 범위가 넓어졌을 때

범위를 정하지 않고 아래처럼 물으면 넓은 답이 나옵니다.

```text
나는 소규모 교육 회사를 운영해.
매주 들어오는 제휴 요청을 처리하는 데 시간이 많이 들어.
제휴 업무에서 자동화할 일을 추천해 줘.
```

같은 대화에서 아래 프롬프트로 범위를 줄입니다.

```text
이 후보는 첫 실습으로 너무 커.
외부 서비스에서 수집하는 단계는 빼 줘.
답장 발송과 일정 등록도 빼 줘.

내가 익명화해서 준비한 요청 목록 다섯 건만 입력으로 사용해.
결과는 검토 순서와 그 근거가 있는 Markdown 파일 한 개로 제한해.
계약 조건과 금액은 판단하지 말고 [사람 검토]로 표시해.
실패해도 원본과 외부 일정이 바뀌지 않는 범위로 다시 작성해 줘.
```

## 잘못된 결과를 바로잡는 대화 ②. 기준이 모호할 때

```text
‘중요한’의 뜻을 내가 판정할 수 있게 바꿔 줘.
이번 실습에서는 일정이 2주 안인지 먼저 확인해.
제안 내용과 희망 결과가 모두 있는지도 표시해.
두 기준으로 순서를 제안하되 최종 순위는 사람이 승인하게 해.
```
