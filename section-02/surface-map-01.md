# 작업 배치표: 받은 요청 정리

| 순서 | 작업 | 종류 | 추천 표면 | 필요한 권한 | 사람이 승인할 지점 |
|---|---|---|---|---|---|
| 1 | 분류 기준 정하기 | 생각 | 채팅 | 권한 없음 | 기준 확정 |
| 2 | 요청 목록 읽기 | 실행 | Cowork | mini-agent 폴더 읽기 | 폴더 선택 |
| 3 | 세 묶음 만들기 | 실행 | Cowork | mini-agent 폴더에 새 파일 생성 (기존 파일 덮어쓰기 없음) | 결과 검토 |
| 4 | 누락된 요청과 긴급 표시 확인하기 | 사람 승인 | 없음 | 권한 없음 | 누락된 요청과 잘못된 긴급 표시 확인 |
| 5 | 할 일 목록에 반영하기 | 사람 승인 | 없음 | 권한 없음 | 할 일 목록 반영 결정 |

## 분류와 다르게 판단한 행

없음. 다섯 행 모두 주어진 분류 기준과 일치한다.

## 채워 넣은 칸

- 3행: 실행 작업이므로 필요한 권한에 폴더 이름(mini-agent)을 넣고, 새 파일 생성만 허용한다는 점을 적었다.
- 4·5행: 사람이 직접 하는 일이므로 추천 표면은 '없음', 필요한 권한은 '권한 없음'으로 적고, 승인 지점은 카드의 확인 항목과 사용할 곳에서 가져왔다.

## 자동 승인하지 않는 행동

삭제, 덮어쓰기, 외부 전송은 자동 승인하지 않으며, 필요해지면 그때마다 사람이 직접 승인한다.

## 구축이 필요 없는 이유

현재 범위는 요청 목록 한 건을 읽어 새 파일 하나를 만드는 30분짜리 시험이라, 반복 도구나 스크립트를 만들지 않고 실행 작업만으로 끝난다.
