# 작업 배치표: 받은 요청 정리

| 순서 | 작업 | 종류 | 맡길 곳 | 필요한 권한 | 사람이 승인할 지점 |
|---|---|---|---|---|---|
| 1 | 분류 기준 정하기 | 생각 | 대화 | 권한 없음 | 기준 확정 |
| 2 | 요청 목록 읽기 | 실행 | 폴더 연결 (mini-agent) | mini-agent 폴더 읽기 (읽기만) | 폴더 선택 |
| 3 | 세 묶음 만들기 | 실행 | 폴더 연결 (mini-agent) | mini-agent 폴더에 새 파일 생성 (기존 파일 덮어쓰기 없음) | 결과 검토 |
| 4 | 누락된 요청과 긴급 표시 확인하기 | 사람 승인 | 없음 | 권한 없음 (사람이 직접 확인) | 누락된 요청 보완, 잘못된 긴급 표시 수정 후 확정 |
| 5 | 할 일 목록에 반영하기 | 사람 승인 | 없음 | 권한 없음 (사람이 직접 반영) | 반영 여부를 정하고 할 일 목록에 직접 반영 |

## 분류 검토

- 종류와 맡길 곳은 다섯 행 모두 내 분류와 같게 판단했다.
- 보완: 3행의 필요한 권한에 폴더 이름(mini-agent)을 넣고, 새 파일만 만들며 기존 파일은 덮어쓰지 않는다는 조건을 덧붙였다.
- 보완: 5행은 기존 할 일 목록을 고치는 일이라 덮어쓰기 위험이 있으므로 에이전트에게 맡기지 않고 사람이 직접 한다.

## 자동 승인 금지

- 삭제, 덮어쓰기, 외부 전송은 자동으로 승인하지 않는다. 필요해지면 그때마다 사람이 직접 승인한다.

## 구축이 필요 없는 이유

첫 카드는 요청 목록 한 건으로 30분 안에 시험해 보는 단계라서 대화와 폴더 연결만으로 충분하고, 반복 도구나 스크립트는 분류 기준이 여러 번 써 본 뒤 굳어졌을 때 만들어도 늦지 않다.
