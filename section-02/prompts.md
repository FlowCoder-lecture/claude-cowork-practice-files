# SECTION 02 프롬프트 모음

책에 실린 [프롬프트 입력]을 순서대로 모았습니다. 회색 상자 안의 글만 복사해 Claude 채팅 입력창에 붙여 넣습니다.
`[… 내용 붙여 넣기]` 자리는 안내한 파일의 내용으로 바꿔 넣습니다.

## 따라 하기 5단계. 프롬프트로 작업 배치표 만들기

- 붙여 넣을 파일: `section-01/work-card-01.md`, `section-02/task-memo-01.txt`(1~4단계에서 직접 적은 작업 메모가 있으면 그것을 씁니다)
- 결과 예시: `section-02/surface-map-01.md`

```text
다음 반복 업무 카드를 작업 배치표로 정리해 줘.

[work-card-01.md 내용 붙여 넣기]

내가 나눈 작업과 분류는 다음과 같아.

[작업 메모 붙여 넣기]

분류 기준은 아래와 같아.
- 생각: 기준 정리, 비교, 초안, 검토 질문
- 실행: 허용한 파일 읽기, 새 문서 생성, 자료 정리
- 구축: 반복 도구, 스크립트, 테스트, 웹서비스 만들기
- 사람 승인: 사람이 직접 확인하거나 결정하는 일

추천 표면은 채팅(대화), Cowork(업무 실행), Code(구축) 중에서 골라 줘.
사람 승인 작업은 추천 표면을 '없음'으로 적어 줘.
실행 작업에는 접근할 폴더 이름을 함께 적어 줘. 실습 폴더는 mini-agent야.

표의 열은 순서, 작업, 종류, 추천 표면, 필요한 권한,
사람이 승인할 지점으로 구성해 줘.
내 분류와 다르게 판단한 행이 있으면 표 아래에 이유를 한 줄씩 써 줘.
삭제, 덮어쓰기, 외부 전송은 자동 승인하지 마.
현재 범위에 구축이 필요 없으면 그 이유도 한 문장으로 써 줘.
결과는 surface-map-01.md에 저장할 내용으로 보여 줘.
```

## 한 걸음 더. 권한 경계 표시하기

- 붙여 넣을 파일: `section-02/surface-map-01.md`
- 결과 예시: `section-02/permission-boundary-01.md`

```text
아래 작업 배치표에서 권한 경계만 따로 정리해 줘.

[surface-map-01.md 내용 붙여 넣기]

행마다 필요한 권한을 아래 세 단계 중 하나로 표시해.
- 읽기: 실습 폴더의 파일을 읽기만 한다.
- 새 파일 생성: 실습 폴더에 새 파일을 만든다. 기존 파일은 바꾸지 않는다.
- 외부 행동: 삭제, 덮어쓰기, 외부 전송처럼 되돌리기 어려운 행동이다.

표의 열은 순서, 작업, 권한 단계, 사람이 승인할 지점으로 해.
외부 행동이 하나도 없으면 '외부 행동 없음'이라고 한 줄로 적어 줘.
결과는 permission-boundary-01.md에 저장할 내용으로 보여 줘.
```

## 사례. 캠페인 회고를 표면으로 나누기

- 결과 예시: `section-02/case-campaign-surface-map.md`

```text
나는 마케터야.
캠페인이 끝날 때마다 광고 결과 CSV, 고객 반응 메모, 기존 회고 양식으로 회고 문서를 만들어 팀 폴더에 올려.
이 일을 작업 단위로 나누고 채팅·Cowork·Code 가운데 어디에 맡길지 배치표로 정리해 줘.
표의 열은 순서, 작업, 종류, 추천 표면, 배치 이유, 대체 방법으로 해.
종류는 생각, 실행, 구축, 사람 승인 가운데 하나로 적어.
사람 승인 작업은 추천 표면을 '없음'으로 적어.
계산 도구는 캠페인 한 건을 먼저 손으로 계산해 지표 이름과 반올림 규칙이 정해진 뒤에만 구축 후보로 표시해.
팀 폴더 반영은 자동 실행하지 말고 사람 승인 단계로 남겨.
```

## 잘못된 결과를 바로잡는 대화 ①. 하나의 도구에 모든 작업이 몰렸을 때

작업을 나누지 않고 아래처럼 도구부터 물으면 한 도구에 모든 작업이 몰린 답이 나옵니다.

```text
나는 마케터야.
캠페인 회고 문서를 만드는 일을 한 번에 끝내고 싶어.
광고 결과 CSV를 읽고 분석해서 문서를 쓰고 팀 폴더에 올리는 것까지 맡길 도구 하나만 추천해 줘.
```

같은 대화에서 아래 프롬프트로 고칩니다.

```text
도구가 아니라 작업의 성격으로 다시 나눠 줘.

먼저 파일을 변경하지 않는 생각 단계를 분리해.
로컬 복사본을 읽고 새 초안을 만드는 실행 단계를 분리해.
반복 계산 규칙이 확정된 경우에만 구축 단계로 표시해.

팀 폴더 업로드는 자동 실행하지 마.
사람이 수치와 근거를 확인한 뒤 승인하는 단계로 남겨.
각 단계에 입력 파일, 출력 파일, 실패 시 멈출 조건을 적어 줘.
```

## 잘못된 결과를 바로잡는 대화 ②. 한 행에 여러 동작이 묶였을 때

```text
한 행에는 동사 하나만 둬.
‘분석하고 작성한다’는 ‘계산한다’와 ‘초안을 만든다’로 나눠.
계산 결과 파일의 이름도 정해 줘.
초안 단계는 그 파일만 읽게 해.
```
