# 롤백 절차

검토 패키지의 `08-rollback.md`로 사용합니다.
세 가지 롤백을 섞지 않습니다. 한 번에 하나만 되돌리고 결과를 확인합니다.

## 1. 배포 롤백
1. 새 배포를 중지한다.
2. 배포 관리 화면에서 known-good(deploy-001)을 선택한다. 이전 배포 선택 기능이 없으면 `request-board-release-1` 폴더를 다시 배포한다.
3. 공개 주소에서 화면 제목과 PROD-A1을 확인한다.
4. 실패했던 시험을 다시 실행한다.
5. 복구 완료 시각을 `release-check.md`에 적는다.

## 2. 모니터 설정 롤백
1. 현재 설정(`monitor-contract-v2.md`)의 예약을 중지한다.
2. 직전 정상 설정(`monitor-contract-v1.md`)을 다시 연결한다.
3. 수동으로 정상 시험 1회, 실패 시험 1회를 실행한다.
4. 두 시험을 모두 통과하면 예약을 재개한다.
5. 설정 롤백은 배포를 바꾸지 않는다. 모니터 문제와 서비스 문제를 분리한다.

## 3. 계약과 검토 규칙 롤백
1. 새 규칙(`review-gate-v2`)이 증거 없는 승인을 허용하는지 확인한다.
2. 허용한다면 즉시 `review-gate-v1`로 되돌린다.
3. 되돌린 뒤 권한, 비용 상한, 중지 책임자를 다시 확인한다.
4. 검토자가 새 판정을 남긴 뒤에만 운영 책임자가 예약을 재개한다.

## 공통 규칙
- 롤백하는 동안에는 기능을 추가하지 않는다.
- 실패 항목과 재현 절차를 기록에 남긴다.
- "롤백 가능"이라고 쓰기 전에 실제로 한 번 연습하고 걸린 시간을 적는다.
